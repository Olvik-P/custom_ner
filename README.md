# PrivacyGuard Pipeline

Трёхслойный конвейер анонимизации PII (персональных данных) перед отправкой в LLM API с возможностью последующей деанонимизации ответа.

Статус: самостоятельный проект. Покрыт автоматическими тестами и проверялся на собственных документах автора; в промышленной эксплуатации и реальными пользователями не использовался. Запускается локально, через Docker, HTTP API или как MCP-сервер.

## Архитектура

```
Входной текст
    │
    ▼
┌─────────────────┐
│  PatternMatcher │  ← Слой 1: Regex (телефоны, email, паспорта, ИНН, СНИЛС, карты, IP, URL, координаты,
│                 │    счета, КПП, ОГРН/ОГРНИП, госномера, ВУ, ОМС, даты рождения, Telegram)
│  (detection/)   │    с валидацией (Luhn для карт, phonenumbers для телефонов)
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   NatashaNER    │  ← Слой 2: Нейросетевой NER (PER, LOC, ORG, адреса)
│  (detection/)   │    Библиотека Natasha от Яндекса
└────────┬────────┘
         │
         ▼
┌─────────────────────┐
│ ContextualValidator │  ← Слой 3: Разрешение конфликтов, whitelist, эвристики,
│     (detection/)    │    морфология; "Ромашка" → цветок, не PER
└────────┬────────────┘
         │
         ▼
┌─────────────────┐
│     Masker      │  ← Генерация токенов <TYPE_UUID8>, замена от конца к началу
│   (masker.py)   │    Сохранение mapping'а в памяти
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   LLM Proxy     │  ← Отправка обезличенного текста в OpenAI/Claude API
│  (llm_proxy.py) │    Получение ответа с токенами
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│    Demasker     │  ← Обратная замена токенов → оригинальные значения
│   (masker.py)   │    Очистка mapping'а из памяти
└────────┬────────┘
         │
         ▼
   Финальный ответ
```

## Установка на Windows

### 1. Установка Python 3.12 через winget

```powershell
winget install Python.Python.3.12
```

Проверьте установку:

```powershell
python --version
# Python 3.12.x
```

### 2. Клонирование и настройка проекта

```powershell
cd privacyguard_pipeline
python -m venv .venv
.venv\Scripts\activate
pip install -e .
```

### 3. Настройка .env

Скопируйте `.env.example` в `.env`:

```powershell
copy .env.example .env
```

Отредактируйте `.env`, укажите ваш API-ключ:

```
OPENAI_API_KEY=sk-your-key-here
LLM_MODEL=gpt-4o-mini
```

### 4. Первый запуск (скачивание моделей Natasha)

При первом запуске модели Natasha скачаются автоматически:

```powershell
python main.py "Тестовый текст"
```

### Программный режим

```python
import asyncio
from main import process


async def main():
    result = await process(
        'Пациент Иванов Пётр Сергеевич, тел. +7(916)123-45-67'

    print(result['llm_response'])
    print(result['stats'])


asyncio.run(main())
```

## Пример работы

**Вход:**
```
Пациент Иванов Пётр Сергеевич, 1975 г.р., адрес: г. Москва,
ул. Тверская, д.5, кв.17, полис ОМС 1234567890123456,
тел. +7(916)123-45-67. Диагноз: гипертония.
```

**Обезличенный текст:**
```
Пациент <PER_F50375AE>, 1975 г.р., адрес: <LOC_40820F6D>,
<LOC_88736FB3>, <LOC_54DE3CD7>, <LOC_F7F136EE>, полис ОМС 1234567890123456,
тел. <PHONE_BF0DE2ED>. Диагноз: гипертония.
```

Каждый компонент адреса - город, улица, дом, квартира - маскируется
отдельным токеном, а не только город/улица целиком (см. "Как это работает"
выше). Номер полиса в этом примере не распознаётся ни одним из типов PII
пайплайна - маскируются только поддерживаемые сущности (ФИО, телефон,
email, паспорт, ИНН, СНИЛС, ОГРН, банковская карта - с проверкой по
алгоритму Луна, из-за чего этот конкретный 16-значный номер не проходит
как карта, - IP, координаты, адрес).

**Финальный ответ (демаскированный):**
```
Пациент Иванов Пётр Сергеевич находится в группе риска по гипертонии.
Рекомендовано наблюдение по месту жительства: г. Москва.
```

## Порог уверенности детекции (`MIN_CONFIDENCE`)

Для типов с неоднозначным форматом (паспорт, СНИЛС, ОГРН, координаты, IP)
каждое regex-совпадение получает оценку уверенности от 0 до 1 вместо
одной фиксированной: базовая оценка типа, плюс бонусы (пройденная
контрольная сумма, ключевое слово рядом - «паспорт», «СНИЛС», «ОГРН»,
«координаты», «IP-адрес»; признак формата), минус штраф за анти-контекст
(«заказ №», «артикул», «версия», «тел.», цена в рублях). Совпадения ниже
порога `MIN_CONFIDENCE` (по умолчанию `0.5`) не маскируются. Строго
валидированные типы (email, карта с верной суммой Луна, ИНН с верной
контрольной суммой, телефон, URL) оценкой не затрагиваются.

| Что | Результат при пороге по умолчанию |
|---|---|
| `паспорт 4510123456` | маскируется (ключевое слово) |
| `45 10 123456` без слова «паспорт» | маскируется (серия парами - признак формата) |
| `4510123456` без слова «паспорт» | не маскируется |
| `заказ № 45 10 123456` | не маскируется |
| СНИЛС/ОГРН с верной контрольной суммой | маскируется и без ключевого слова |
| СНИЛС/ОГРН с опечаткой, но со словом «СНИЛС»/«ОГРН» | маскируется |
| `55.751244, 37.618423` или `координаты 55.75, 37.61` | маскируется |
| `цена 12.5, 3.7` | не маскируется |
| `IP-адрес 192.168.1.10` | маскируется |
| `версия 1.2.3.4`, голый `84.201.12.5` без слова | не маскируется |

Порог можно изменить тремя способами:

- в `.env`: `MIN_CONFIDENCE=0.5` (`0` - вернуть прежнее поведение без
  фильтрации, `1` - маскировать только то, в чём система уверена полностью);
- на один HTTP-запрос: поле `min_confidence` в теле `POST /v1/anonymize` и
  form-поле в `POST /v1/anonymize/pdf`;
- на один вызов MCP-инструмента `mask`, `mask_file`, `anonymize_pdf`,
  `detect`: необязательный аргумент `min_confidence`.

Значение вне диапазона 0.0-1.0 отклоняется ошибкой (HTTP 422 / ошибка
инструмента), а не обрезается молча.

> **Обмен полноты на точность.** Порог снижает ложные срабатывания на
> номерах заказов, ценах и версиях, но тот же механизм означает, что
> голый паспорт без слова «паспорт» рядом и без парной записи серии, а
> также IP-адрес без слова «IP»/«адрес» рядом больше не маскируются по
> умолчанию. Если для вашего сценария пропуск PII хуже лишнего
> маскирования, поставьте `MIN_CONFIDENCE=0`.

## Морфология и списки allow/deny

### Морфологический фильтр имён

Падежи и омонимия - главный источник ложных PER у Natasha. Поверх неё
работает морфологический слой (`pymorphy3`):

- «Надежды», «Веры», «Ромашки» отбрасываются так же, как «Надежда»,
  «Вера», «Ромашка»: whitelist сверяется по лемме (только для одиночного
  слова; «Вера Петрова» остаётся ФИО).
- Одиночное словарное слово без чтений имени/фамилии/отчества («Рыба»,
  «Корень») не считается персоной, если перед ним нет маркера
  («гражданин», «пациент», «клиент», «г-н», «ФИО» и т.п.). Слова вне
  словаря и топонимы этим фильтром не затрагиваются.
- Тип PER/LOC решается по грамматическим признакам: «от Иванова»,
  «к Петрову», «у Сидорова» остаются PER, «в Москве» - LOC; если словарь
  ничего не говорит, действует прежняя эвристика предлога/глагола.

Если `pymorphy3` или его словарь не загрузились, фильтры выключаются с
предупреждением в логе (как у Natasha), действует прежнее поведение.

### Allow- и deny-списки

Оператор может задать строки, которые **никогда не маскируются** (allow)
и которые **маскируются всегда** (deny, тип `CUSTOM`):

```env
ALLOW_LIST=["ООО Ромашка", "support@corp.example"]
DENY_LIST=["Проект Заря", "Кодовое имя Икс"]
```

(JSON-массивы строк в `.env`.) Записи - литеральные строки, не regex.

- **allow**: подавляется спан, который *целиком* равен записи после
  нормализации: регистр, `ё`/`е`, кавычки, пробелы, ведущее
  «ООО/АО/ПАО/ЗАО/ОАО/ИП» не важны, слова сравниваются по лемме, строка из
  7+ цифр - по цифрам. Совпадение по подстроке спан не подавляет
  («Ромашкин Пётр» при allow «Ромашка» маскируется).
- **deny**: запись ищется во всём тексте в любой форме слова и в любом
  регистре, по границам слов («Заря» не найдёт «зарядка»); совпадение
  маскируется независимо от `MIN_CONFIDENCE` и whitelist. Если оно
  пересекается со спаном другого слоя, охват расширяется до объединения, а
  тип существующего спана сохраняется.
- Если строка есть и в allow, и в deny, она **маскируется** (deny сильнее).
- Списки на вызов **добавляются** к спискам из `.env` и ничего из них
  убрать не могут; на следующий вызов они не влияют.
- Невалидная запись (пустая после нормализации, длиннее 200 символов,
  больше 500 записей в списке) отклоняется ошибкой (HTTP 422 / ошибка
  инструмента) до обработки. Содержимое списков не попадает в логи,
  аудит и тексты ошибок - только количество записей.

Списки на один вызов:

- HTTP: поля `allow_list` и `deny_list` в теле `POST /v1/anonymize` и
  повторяющиеся form-поля с теми же именами в `POST /v1/anonymize/pdf`;
- MCP: необязательный аргумент `deny_list` у `mask`, `mask_file`,
  `anonymize_pdf`, `detect`. **`allow_list` через MCP не принимается**:
  агент, которого сервер защищает от сырого PII, не должен иметь
  возможности ослабить маскирование (например, по инструкции, спрятанной
  в обрабатываемом документе). Исключения задаёт только оператор в `.env`.

> **Компромисс.** Настоящая фамилия, совпадающая со словарным словом
> («Гусь», «Волк»), без маркера персоны и без имени рядом отбрасывается
> как существительное; так же отбрасывается название улицы, которое
> Natasha пометила как PER, если оно словарное слово без «ул.» рядом
> («адрес Речная 63»). Для таких случаев есть deny-список.

## Российские идентификаторы с проверяемым форматом

Для каждого типа формат проверяется жёстко (невозможное не детектируется), а
неоднозначное требует подтверждения контекстом: ключевого слова рядом или
контрольной суммы. Баллы складываются так же, как у паспорта и СНИЛС, и
отсекаются порогом `MIN_CONFIDENCE`; при `MIN_CONFIDENCE=0` вернутся и голые
кандидаты.

| Тип | Что ловит | Когда маскируется по умолчанию |
|---|---|---|
| `BANK_ACCOUNT` | 20-значный расчётный или корреспондентский счёт | ключ счёта сошёлся с БИК рядом; либо допустимые префикс и код валюты (голый настоящий счёт тоже); либо слово «р/с», «счёт», «к/с» с допустимым префиксом. «трек», «заказ» рядом снимают |
| `KPP` | КПП (9 знаков) | только со словом «КПП»; код региона из справочника ФНС, причина постановки не `00` |
| `OGRNIP` | 15-значный ОГРНИП с контрольной цифрой | как `OGRN`: по контрольной цифре или слову «ОГРН/ОГРНИП» |
| `CAR_PLATE` | госномер (`А123ВС77`, `К777ХН 799`, латинские двойники) | всегда, если буквы допустимы, а регион есть в перечне |
| `DRIVER_LICENSE` | водительское удостоверение (серия, номер) | при слове «водительское», «в/у» рядом; иначе это паспорт |
| `OMS` | единый номер полиса ОМС (16 цифр, Mod10) | только со словом «полис», «ОМС», «ЕНП»; без слова остаётся картой |
| `BIRTHDATE` | дата рождения | только рядом со словом «рождения», «родился», «г.р.»; реальная дата, возраст не больше 120 лет |
| `TELEGRAM` | `@ник` и `t.me/ник` | ник - со словом «телеграм», «tg»; ссылка `t.me` - всегда |

`CVC` и API-токены сознательно не включены: у них нет проверяемого формата.

> **Смена типа.** 15-значный ОГРНИП теперь имеет тип `OGRNIP`, а не `OGRN`:
> меняются токен (`<OGRNIP_…>`) и тип в статистике. Если вы фильтруете PDF
> по `entity_types=['OGRN']`, добавьте `OGRNIP`.

Справочники (регионы на знаках, коды субъектов ФНС для КПП, балансовые счета
по Положению Банка России № 809-П, коды валют) лежат в `constants.py` с
указанием источника и даты сверки. Справочник регионов на знаках составлен по
Википедии, сверенной с ria.ru; официального перечня МВД в открытом виде
найти не удалось, поэтому он может отставать от реестра.

## Обезличивание PDF

Помимо текстового конвейера, пакет умеет обезличивать PII прямо в PDF-файлах
(`privacyguard_pipeline/pdf/`) - договорах, сканах и т. п. Найденные
фрагменты **физически удаляются** из файла (текстовые объекты вырезаются,
пиксели изображений под областью редакции закрашиваются), а не просто
скрываются чёрным прямоугольником поверх текста, который оставался бы
извлекаемым.

### Установка

Это опциональная зависимость - базовый текстовый/LLM-пайплайн её не требует:

```powershell
cd privacyguard_pipeline
pip install -e ".[pdf]"
```

Для страниц без текстового слоя (сканы) используется OCR-фолбэк на базе
`pytesseract`, которому дополнительно нужен **системный** Tesseract с
русской языковой моделью - он не ставится через `pip`:

```powershell
winget install --id UB-Mannheim.TesseractOCR
```

Убедитесь, что `tesseract.exe` есть в `PATH` и что вместе с ним установлен
языковой пакет `rus` (в installer'е UB-Mannheim он отмечается отдельным
чекбоксом "Russian").

> OCR-путь менее надёжен, чем текстовый слой: ошибки распознавания
> (спутанные цифры, "0"/"O" и т. п.) могут привести к тому, что PII на
> сканированной странице не будет найдена. Используйте статистику результата
> (`redacted_by_type`, `pages_processed`), чтобы заметить страницы с
> подозрительно малым числом найденных PII, и проверяйте такие страницы
> вручную.

### Использование

```python
from privacyguard_pipeline import PDFAnonymizer

anonymizer = PDFAnonymizer()
result = anonymizer.anonymize(
    input_pdf='договор.pdf',
    output_pdf='договор_обезличенный.pdf',
    # entity_types=["PER", "PHONE"],  # только эти типы, если задано
)

print(f'Обработано страниц: {result.pages_processed}')
print(f'Найдено PII: {result.total_spans_redacted}')
print(f'По типам: {result.redacted_by_type}')
print(f'Успех: {result.success}')
```

Если `pdf`-зависимости не установлены, обращение к `PDFAnonymizer` выдаёт
понятную ошибку `PDFDependencyError` с инструкцией по установке - при этом
импорт остальной части пакета (текстовый/LLM-пайплайн) не затрагивается.

## HTTP API

Помимо CLI/программного использования, пакет умеет отдавать тот же
конвейер по HTTP - чтобы его можно было переиспользовать из других
проектов независимо от языка/стека (не на Python, без Docker и т. п.),
а не только встраивать как Python-зависимость. Это тонкий слой поверх
уже существующего `PrivacyGuardPipeline.process()` / `PDFAnonymizer` -
никакой новой логики детекции/маскирования/LLM-проксирования,
только HTTP-обёртка.

### Установка

Опциональная зависимость - базовый текстовый/LLM-пайплайн и CLI её не
требуют:

```powershell
cd privacyguard_pipeline
pip install -e ".[api]"
```

Ставит FastAPI, uvicorn и python-multipart (нужен FastAPI для разбора
multipart-загрузки файлов в `/v1/anonymize/pdf`).

### Настройка

В `.env` (см. `.env.example`):

```
API_KEY=ваш-секретный-ключ
API_KEY_REQUIRED=true
API_PORT=8420
```

- **`API_KEY`** - секрет, который клиенты передают в заголовке
  `X-API-Key`. Сверяется constant-time сравнением
  (`hmac.compare_digest`), чтобы не давать утечку через тайминг-атаку.
- **`API_KEY_REQUIRED=false`** отключает проверку ключа - только для
  локальной разработки. При старте с отключённой проверкой сервис
  всегда пишет явное предупреждение в лог (независимо от `LOG_LEVEL`),
  чтобы такая конфигурация не осталась незамеченной на реальном
  окружении.
- **`API_PORT`** - порт, который слушает сервер (по умолчанию `8420` -
  умышленно не 8000/8080/5000/3000, чтобы не пересекаться с типичными
  занятыми портами других сервисов).

### Запуск

Локально (после `pip install -e ".[api]"`):

```powershell
cd privacyguard_pipeline
python -m privacyguard_pipeline.api
```

Через Docker - см. раздел "Docker" ниже.

### Эндпоинты

Все, кроме `/health`, требуют заголовок `X-API-Key` - без него или с
неверным значением сервер отвечает `401 Unauthorized`, не выполняя
никакой обработки PII.

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/health` | Liveness-check, без аутентификации, без PII |
| POST | `/v1/anonymize` | `{text, system_prompt?, min_confidence?, allow_list?, deny_list?}` → `{anonymized_text, llm_response, stats}` |
| POST | `/v1/anonymize/pdf` | multipart PDF (+ form-поля `min_confidence?`, `allow_list?`, `deny_list?`) → редактированный PDF (нужна `pdf`-экстра) |
| GET | `/v1/stats` | Статистика сессии - только типы/количества сущностей |

#### `POST /v1/anonymize`

```bash
curl -X POST http://localhost:8420/v1/anonymize \
    -H "X-API-Key: ваш-секретный-ключ" \
    -H "Content-Type: application/json" \
    -d '{"text": "Пациент Иванов Пётр Сергеевич, тел. +7(916)123-45-67"}'
```

Ответ - та же структура, что уже возвращает программный
`PrivacyGuardPipeline.process()`:

```json
{
  "anonymized_text": "Пациент <PER_C7D2F8E2>, тел. <PHONE_98D31C0A>",
  "llm_response": "Имя пациента: Иванов Пётр Сергеевич\nТелефон: +7(916)123-45-67",
  "stats": {
    "entity_counts": {"PER": 1, "PHONE": 1},
    "total_entities_detected": 2,
    "processing_time_ms": 95.01
  }
}
```

Каждый запрос получает собственный экземпляр `Masker` - соответствие
токен→значение одного запроса никогда не видно и не может быть
очищено другим параллельным запросом (проверено вручную двумя
одновременными запросами с разным PII). Детектор PII и LLM-прокси при
этом общие на процесс (создаются один раз при старте) - это не
PII-хранящее состояние, а переиспользование дорогого в создании
ресурса: пересоздание детектора на каждый запрос заново грузило бы
модели Natasha, а пересоздание LLM-прокси теряло бы пул HTTP-соединений.

#### `POST /v1/anonymize/pdf`

```bash
curl -X POST http://localhost:8420/v1/anonymize/pdf \
    -H "X-API-Key: ваш-секретный-ключ" \
    -F "file=@договор.pdf;type=application/pdf" \
    -o договор_redacted.pdf
```

Тело ответа - редактированный PDF (`application/pdf`), статистика идёт
в заголовках, а не в теле, так как тело занято файлом:

| Заголовок | Значение |
|-----------|----------|
| `X-Pages-Processed` | число обработанных страниц |
| `X-Total-Spans-Redacted` | всего вычеркнуто PII-фрагментов |
| `X-Redacted-By-Type` | JSON вида `{"PER": 4, "PHONE": 2, ...}` |

Загрузка ограничена 20 МБ (`413 Request Entity Too Large` при
превышении). Если `pdf`-зависимости не установлены - `501 Not
Implemented` с понятным текстом ошибки, а не общий сбой. Если
редактирование не удалось (повреждённый файл и т. п.) - `422
Unprocessable Entity`.

#### `GET /v1/stats`

Отдаёт то же, что `AuditLogger.get_stats()` - только типы/количества
найденных сущностей за сессию, никогда исходные или демаскированные
значения:

```json
{
  "session_duration_seconds": 30.75,
  "total_requests": 2,
  "successful_requests": 2,
  "failed_requests": 0,
  "entity_counts": {"PER": 4, "PHONE": 3},
  "total_entities_detected": 7
}
```

## MCP-сервер

Локальный MCP-сервер защищает не вызов внешнего LLM API (для этого уже
есть HTTP API выше), а саму модель-агента (например, Claude
Desktop/Code), которая работает с текстом/файлами пользователя через
MCP: инструменты обезличивают содержимое до того, как оно попадёт в
контекст агента. Работает поверх stdio как локальный дочерний процесс,
запускаемый самим MCP-хостом - без сетевого порта и без API-ключа
(доверие обеспечивается тем, что процесс порождён самим хостом).

### Установка

```powershell
cd privacyguard_pipeline
pip install -e ".[mcp]"
```

Для инструмента `anonymize_pdf`/`detect` по PDF дополнительно нужна
экстра `pdf` (`pip install -e ".[pdf,mcp]"`).

### Настройка

В `.env` (см. `.env.example`):

```
MCP_HANDLE_TTL_SECONDS=300
```

`mask` и `demask` - два разных вызова в рамках одного диалога:
`mask` возвращает handle, `demask` принимает его позже. Если `demask`
так и не был вызван (диалог прерван и т. п.), запись handle → PII
автоматически удаляется из памяти процесса по истечении этого TTL.

### Запуск

Настройте MCP-хост (например, Claude Desktop/Code) на запуск локальной
команды:

```json
{
  "mcpServers": {
    "privacyguard-pipeline": {
      "command": "python",
      "args": ["-m", "privacyguard_pipeline.mcp_server"],
      "env": { "MCP_HANDLE_TTL_SECONDS": "300" }
    }
  }
}
```

Через Docker (тот же образ, что и для HTTP API - см. раздел "Docker"
ниже; обязательно `-i`, без `-p`, так как транспорт здесь stdio, а не
сеть) - контейнер поднимается заново на каждый такой запуск, подходит
для разовой ad hoc проверки:

```bash
docker run -i --env-file privacyguard_pipeline/.env ner-pipeline python -m privacyguard_pipeline.mcp_server
```

Через Docker Compose (один долгоживущий контейнер, без запуска нового
контейнера на каждую MCP-сессию) - `docker-compose.yml` в корне
репозитория держит контейнер `mcp-ner-pipeline` поднятым (`sleep
infinity`), а MCP-хост порождает сам процесс сервера отдельно на каждую
сессию через `docker exec`. Полезно, когда сам Docker и его изоляция
нужны (например, деплой на машину без настроенного Python/Tesseract) -
для локальной разработки, где вы хотите обращаться к произвольным файлам
любого своего локального проекта без перенастройки volume при каждом
переключении, обычный запуск через venv (пример выше) проще: процесс на
venv видит файловую систему хоста целиком, а не только то, что явно
смонтировано в контейнер.

```bash
# Разово: скопировать .env.example в .env, указать MCP_HOST_DOCUMENTS_DIR
# (директория на хосте с документами для mask_file/detect/anonymize_pdf -
# монтируется в /workspace внутри контейнера), затем поднять контейнер
cp .env.example .env
docker compose up -d --build
```

```json
{
  "mcpServers": {
    "privacyguard-pipeline": {
      "command": "docker",
      "args": ["exec", "-i", "mcp-ner-pipeline", "python", "-m", "privacyguard_pipeline.mcp_server"]
    }
  }
}
```

Пути, которые передаются в `mask_file`/`detect`/`anonymize_pdf`, в этом
случае должны быть путями **внутри контейнера** (`/workspace/...`), а не
хостовыми - сервер читает файлы на своей стороне. MCP-сервер не
хот-релоадится, поэтому после `docker compose up -d --build` с новым
образом нужна новая сессия MCP-хоста.

### Инструменты

| Инструмент | Вход | Выход |
|---|---|---|
| `mask` | `text`, `min_confidence?`, `deny_list?` | `{masked_text, handle}` |
| `demask` | `handle, text` | `{text}` |
| `mask_file` | `file_path`, `min_confidence?`, `deny_list?` | `{masked_path, handle}` |
| `close_masked_file` | `handle` | `{status}` |
| `anonymize_pdf` | `input_path`, `output_path?`, `min_confidence?`, `deny_list?` | `{output_path, pages_processed, total_spans_redacted, redacted_by_type}` |
| `detect` | `file_path`, `min_confidence?`, `deny_list?` | `{entity_counts}` (текст) или `{pages: {"1": {...}, ...}}` (PDF) |

`min_confidence` (0.0-1.0) переопределяет порог детекции только для этого
вызова, см. "Порог уверенности детекции" выше. `deny_list` - строки,
которые нужно маскировать всегда (тип `CUSTOM`), поверх `DENY_LIST` из
настроек сервера; он только усиливает маскирование. Allow-список через MCP
не принимается вовсе, см. "Морфология и списки allow/deny" выше.

- **`mask`/`demask`** - реальные значения PII никогда не входят в
  ответ `mask`. Содержательную обработку между ними (то, что раньше
  делал внешний LLM API в HTTP-пути) выполняет сам вызывающий агент -
  ни один из этих инструментов не обращается к LLM API. Повторный
  `demask` с уже использованным или неизвестным/просроченным `handle`
  завершается ошибкой инструмента.
- **`mask_file`/`close_masked_file`** - тот же принцип, что у `mask`, но
  для локального файла (текстового или PDF), который агенту иначе
  пришлось бы прочитать напрямую, минуя сервер. Сервер сам читает файл
  (для PDF - извлекает текст постранично, включая OCR-фолбэк) и
  возвращает путь к плоскому текстовому файлу с PII, заменённым на
  токены, вместе с `handle` - содержимое в ответе на сам вызов не
  передаётся. Демаскирование, как и у `mask`, происходит через `demask`
  с тем же `handle`, но только в тексте ответа агента - сам
  маскированный файл никогда не демаскируется, а просто удаляется с
  диска (автоматически при `demask`, либо явно через
  `close_masked_file`, если ответ не должен содержать реальные значения
  PII вовсе - например, "есть ли в документе пункт про сроки").
- **`anonymize_pdf`** - то же необратимое редактирование PDF, что и в
  `POST /v1/anonymize/pdf` выше, но без HTTP: сервер сам читает
  `input_path` и пишет результат по `output_path` (или рядом с
  исходником, если не задан) - содержимое файла не передаётся ни в
  запросе, ни в ответе инструмента, только путь и статистика. Прочитать
  результат можно напрямую с диска. Пары для восстановления нет -
  редактирование необратимо.
- **`detect`** - сервер сам читает файл по переданному пути; ни
  содержимое файла, ни сами значения найденного PII не попадают в
  ответ, только количество сущностей по типу (постранично для PDF).
  Полезно как быстрая проверка "что вообще есть в этом файле" перед
  тем, как решать, гнать ли его через `mask_file`/`anonymize_pdf`, или
  можно читать напрямую (если сущностей не найдено).

## Качество детекции (pii-bench)

Качество измерено на открытом русскоязычном бенчмарке
[hivetrace/pii-bench](https://huggingface.co/datasets/hivetrace/pii-bench)
(Apache-2.0, 900 текстов в сценарной выборке `domain` и 910 в диагностической
`entity`, 13 типов PII, разметка по символам). Версия пакета 1.5.0, порог
`MIN_CONFIDENCE=0.5`, Natasha доступна. Как воспроизвести - в разделе
"Оценка качества детекции" ниже.

> **Как читать цифры.** Главная метрика - **recall утечки**: какая доля
> символов размеченного PII закрыта хотя бы одним спаном детектора,
> независимо от типа. Ошибка типа не делает значение утечкой, пропуск
> делает. Бенчмарк синтетический (его тексты сгенерированы LLM) и короткий,
> поэтому это измерение *на нём*, а не гарантия на ваших документах.

### Сводка (`domain`, 900 текстов)

| Показатель | Значение |
|---|---|
| Recall утечки, типы, которые поддерживает пакет | **92.1%** (10 830 из 11 764 символов) |
| Recall утечки, все 13 типов бенчмарка | 86.8% (10 920 из 12 579 символов) |
| Детерминированные типы (телефон, карта, ИНН, СНИЛС, ОГРН, ОГРНИП, КПП) | **100%** |
| Email / паспорт / ФИО | 98.8% / 97.3% / 93.5% |
| Точность типа среди найденного | **98.0%** |
| Ложно закрытые символы | **2.9%** |
| Тексты без PII, где детектор что-то нашёл | 10 из 378 (2.6%) |

| `domain`: относительный recall (любое пересечение) | 91.5% | **94.7%** | +3.2 п.п. |
| `domain`: строгая precision | 64.3% | **67.0%** | +2.7 п.п. |
| `domain`: КПП, recall утечки | 0% | **100%** | +100 п.п. |
| `domain`: ОГРНИП, строгий recall | 0% | **100%** | +100 п.п. |
| `entity`: recall утечки, все типы | 59.4% | **62.8%** | +3.4 п.п. |
| `entity`: строгий recall | 57.0% | **72.3%** | +15.3 п.п. |
| `entity`: КПП, recall утечки | 0% | **98.6%** | +98.6 п.п. |
| `entity`: ложные символы | 2.8% | **2.6%** | −0.2 п.п. |
| `domain`: ложные символы | 2.88% | 2.94% | +0.06 п.п. |

Рост ложных символов на `domain` целиком из одного спана: в контактах
резюме стоит «telegram @developer_pro» - это настоящий ник, но в разметке
бенчмарка нет типа Telegram, поэтому он считается лишним. Строка
«unsupported» в `compare` для этого сравнения не показательна: из неё
ушли `KPP` и `OGRNIP`, и состав группы изменился.

На реальных PDF результат до и после идентичен - ложных срабатываний новые
типы не добавили.

Ложные срабатывания расчётного счёта оценены отдельно, на 100 000 случайных
20-значных числах: `BANK_ACCOUNT` появился в 12 случаях (0.012%),
то есть примерно один на 8 000.

### Где слабее всего

| Сценарий | Recall утечки | Ложные символы | Комментарий |
|---|---:|---:|---|
| `S-SUPPORT` | 54.3% | 1.7% | 47% PII-символов сценария - токены и CVC, типы без проверяемого формата |
| `S-DELIVERY` | 84.1% | 0.1% | все пропуски - адреса в свободной форме |
| `S-RE` | 88.6% | 0.5% | |
| `L-DIALOG` | 94.4% | **13.4%** | 14 из 17 ложных спанов - `LOC` (города и места вне разметки бенчмарка) |
| `L-CHAT` | 100% | 0.0% | |

Про «ложные символы» стоит знать одну тонкость. В разметке бенчмарка нет
организаций и городов вне адреса, поэтому любой `ORG`-спан засчитывается
как ложный (77% символов `ORG`), а `LOC` - частично. Это ограничение разметки,
а не обязательно ошибка пакета: название компании может быть нужно
скрыть. Но это же честная оценка «лишнего маскирования» по меркам
бенчмарка.

### К чему стремиться

Ориентиры, а не обещания: цифры будут пересматриваться по мере измерений.

| Направление | Сейчас | Цель | Как |
|---|---:|---:|---|
| Recall утечки, поддерживаемые типы | 92.1% | ≥ 95% | адреса без «ул./д.», ФИО в нижнем регистре |
| Recall утечки по `ADDRESS` | 74.1% | ≥ 85% | эвристика «название + номер дома», свой словарь улиц |
| Recall утечки, все 13 типов | 86.8% | ≥ 92% | остались `CVC` и `TOKEN` (вне объёма: нет проверяемого формата); основной резерв - адреса и ФИО |
| Recall по ФИО, нижний регистр / неформальная речь | 93.5% | ≥ 97% | нормализация регистра перед NER |
| Ложные символы в целом | 2.9% | ≤ 2% | отдельная оценка `ORG`/`LOC`, а не только `PER` |
| Тексты без PII с ложным срабатыванием | 2.6% | ≤ 1.5% | скоринг спанов Natasha, не только pattern |
| Сценарий `L-DIALOG`, ложные символы | 13.4% | политика по `LOC` | решить, маскировать ли города и места вне адреса; сейчас они считаются ложными |

И то, чего пока нет вовсе:

- **Сравнения с другими системами на том же бенчмарке.** Мы не
  прогоняли на нём Presidio и другие российские анонимайзеры, поэтому
  утверждать «лучше» или «хуже» нельзя. Честное сравнение - прогнать их на
  той же ревизии `pii-bench` и посмотреть на тот же recall утечки. Из
  просмотренных нами в обзоре 2026-09-29 российских аналогов ни один не
  делал контекстного скоринга и морфологии, но это качественное наблюдение
  без повторной проверки, а не измеренное преимущество.
- **Реальных документов в выборке.** Бенчмарк синтетический; реальные PDF
  проверялись вручную и не образуют воспроизводимого набора.
- **Измерения сквозной утечки через LLM** и необратимости редакции PDF.

## Оценка качества детекции

`privacyguard_pipeline/evaluation/` измеряет детекцию на русскоязычном
бенчмарке [hivetrace/pii-bench](https://huggingface.co/datasets/hivetrace/pii-bench)
(Apache-2.0, 13 типов, посимвольная разметка). Датасет скачивается по
закреплённой ревизии в `.eval_cache/` (вне git) и требует экстру `eval`:

```powershell
pip install -e ".[eval]"
python -m privacyguard_pipeline.evaluation run --config domain
python -m privacyguard_pipeline.evaluation run --config entity --min-confidence 0.3
python -m privacyguard_pipeline.evaluation show путь\к\снимку.json
python -m privacyguard_pipeline.evaluation compare до.json после.json
```

`run` печатает таблицу и сохраняет JSON-снимок (в `.eval_cache/results/` или
в `--output`) с метаданными: версия пакета, git-коммит, ревизия датасета,
порог уверенности, доступность Natasha. `--dump-errors` пишет промахи
(id, тип, оффсеты, без текстов). `compare` отказывается сравнивать снимки с
разной ревизией или конфигурацией датасета и предупреждает о разном пороге.
Базовые снимки лежат в `privacyguard_pipeline/evaluation/baselines/`.

Метрики. Главная — **recall утечки**: доля символов золотой PII-разметки,
покрытых хотя бы одним найденным спаном, независимо от типа (ошибка типа не
делает значение утечкой, пропуск делает). Рядом: строгие метрики по
сущностям (совпадение границ и типа), мягкие (пересечение), точность типа,
доля ложных символов и число ложных спанов на примерах без PII. Типы
бенчмарка `CVC`, `TOKEN` в пакете не поддерживаются:
они входят в общий recall утечки, но показываются отдельной группой и не
считаются ошибкой типа. Адрес детектор разбивает на компоненты, поэтому
строгий recall по `ADDRESS` низкий по построению — смотрите recall утечки.

Ограничения. Датасет синтетический (сгенерирован LLM), тексты короткие, на
нём нельзя обучать и под него нельзя подгонять правила детектора — это
held-out тест. Цифры на нём не заменяют проверку на реальных документах и
PDF. Прогоны с недоступной Natasha несопоставимы по PER/LOC.

## Docker

Образ (`python:3.12-slim` + системный Tesseract с русской моделью +
все Python-зависимости, включая `pdf`-, `api`- и `mcp`-экстры) избавляет от
ручной настройки Windows-окружения - не нужно ни `winget`, ни
выставлять `PATH`/`TESSDATA_PREFIX` вручную, ни ставить FastAPI
локально.

Команды ниже написаны так, чтобы копироваться один в один и в PowerShell, и
в Git Bash/WSL/cmd.exe - одна строка на команду, прямые слэши в путях (не
`\`, который в bash обрезает следующий символ - `privacyguard_pipeline\.env`
в bash превращается в `privacyguard_pipeline.env` и валится с "file not
found").

```bash
# Собрать образ (из корня репозитория)
docker build -t ner-pipeline .

# По умолчанию контейнер поднимает HTTP API и слушает порт 8420 -
# см. раздел "HTTP API" выше. --name делает имя контейнера постоянным
# (ner-pipeline), а не случайно сгенерированным при каждом запуске
docker run --name ner-pipeline --env-file privacyguard_pipeline/.env -p 8420:8420 ner-pipeline

# CLI остаётся доступным в том же образе через переопределение команды
docker run --env-file privacyguard_pipeline/.env ner-pipeline python main.py "Пациент Иванов Пётр Сергеевич, тел. +7(916)123-45-67"

# Без ключа - пайплайн отработает детекцию/маскирование и корректно
# деградирует на шаге обращения к LLM
docker run ner-pipeline python main.py "Текст с PII"

# Интерактивная оболочка внутри контейнера
docker run -it ner-pipeline bash

# Обезличивание PDF с файлами с хоста через volume
docker run -v ${PWD}:/data ner-pipeline python -c "from privacyguard_pipeline import PDFAnonymizer; PDFAnonymizer().anonymize('/data/in.pdf', '/data/out.pdf')"
```

Раз имя контейнера постоянное, повторный `docker run --name ner-pipeline
...` при уже существующем (даже остановленном) контейнере с этим именем
упадёт с `Conflict. The container name "/ner-pipeline" is already in
use`. Чтобы просто перезапустить уже созданный контейнер - `docker start
ner-pipeline`; чтобы пересоздать его заново (например, после
`docker build` новой версии образа) - сначала `docker rm -f
ner-pipeline`, затем повторить `docker run`.

> Образ и контейнер раньше назывались `privacyguard-pipeline` - если у
> вас остался запущенный контейнер под старым именем, снимите его
> командой `docker rm -f privacyguard-pipeline` перед переходом на
> `ner-pipeline`.

Образ можно использовать и как базовый (`FROM ner-pipeline`)
для Dockerfile'ов других проектов, которым нужен этот пайплайн, - не
только запускать напрямую.

### Смоук-тесты через Docker

`docker_test.py` и `docker_test_pdf.py` в корне репозитория монтируют
весь репозиторий в контейнер (`/workspace`), поднимают там HTTP API
(`python -m privacyguard_pipeline.api`) и реально бьют по нему по
HTTP - `POST /v1/anonymize` и `POST /v1/anonymize/pdf` соответственно
- так же, как это делал бы внешний клиент. Поскольку сервер стартует
из смонтированного `/workspace`, тестируется **текущий код с диска**,
а не то, что было запечено в образ при последней сборке - не нужно
пересобирать образ между правками ради проверки. Оба скрипта сами
поднимают и останавливают контейнер (порт `8420`, случайный/фиксированный
тестовый `API_KEY` - не тот, что в вашем `.env`):

```bash
docker build -t ner-pipeline .   # один раз

python docker_test.py                     # текстовый пайплайн через API
python docker_test_pdf.py [in.pdf] [out.pdf]  # PDF через API,
                                               # включая OCR-фолбэк
                                               # (Tesseract уже внутри
                                               # образа)
```

## Ключевые возможности

- **Трёхслойная детекция**: Regex + Natasha NER + контекстная валидация
- **Graceful degradation**: при недоступности Natasha работает только PatternMatcher
- **Безопасность**: mapping токен→значение только в RAM, очищается после ответа
- **Асинхронность**: полная async/await архитектура
- **Аудит**: логирование типов PII (не значений!), статистика сессии
- **Edge cases**: телефоны без пробелов, слитные паспорта, омонимы
- **Измеримое качество**: воспроизводимая оценка на открытом бенчмарке
  pii-bench (recall утечки 91.7% на поддерживаемых типах), снимки до/после
  для каждого изменения детекции - см. "Качество детекции"
- **Обезличивание PDF**: та же детекция, но с необратимой редакцией внутри
  PDF-файлов (текстовый слой + OCR-фолбэк для сканов)
- **HTTP API**: тот же конвейер поверх аутентифицированного HTTP-интерфейса
  для переиспользования из других проектов/языков (опционально)
- **MCP-сервер**: локальный stdio-сервер (`mask`/`demask`/`anonymize_pdf`/
  `detect`), защищающий вызывающего MCP-агента от прямого доступа к сырым
  значениям PII (опционально)

## Безопасность

- API-ключи (LLM и HTTP API) читаются из `.env`, никогда не логируются
- Словарь соответствий (токен → значение) существует только в RAM
- После получения ответа от LLM словарь немедленно очищается
- В лог попадают только типы сущностей, не значения
- Обезличивание PDF физически удаляет PII из файла (`add_redact_annot` +
  `apply_redactions`), а не рисует прямоугольник поверх извлекаемого текста
- HTTP API: `X-API-Key` сверяется constant-time сравнением
  (`hmac.compare_digest`); каждый запрос на анонимизацию получает
  собственный `Masker`, изолируя маскирование от параллельных запросов
- MCP-сервер: ни один инструмент не обращается к внешнему LLM API;
  соответствие `handle → Masker` живёт только в памяти процесса и
  автоматически удаляется по TTL, если `demask` так и не был вызван

## Известные ограничения

Детекция не даёт гарантии полноты: маскируются только поддерживаемые типы
PII, и у каждого слоя есть известные пробелы.

- Обфусцированные адреса (например, `ivan [at] mail.ru`) не распознаются
  как email.
- ФИО, записанные ЗАГЛАВНЫМИ буквами, распознаются неполностью (например,
  может быть найдена только фамилия).
- Расчётный счёт маскируется целиком, если подтверждён БИК рядом, словом
  «р/с» и подобными или структурой номера (допустимые префикс и код валюты).
  20-значное число без этих признаков не маскируется, а в части случаев
  (примерно в четверти случайных чисел) его фрагмент из десяти цифр,
  похожий на телефон, маскируется отдельно, и остаток остаётся открытым.
  Счета в экзотической валюте и новые казначейские счета с префиксом 03100
  без слова «счёт» и без БИК структурой не опознаются.
- Ложные срабатывания на числовых последовательностях, похожих на PII
  (пары десятичных чисел, номера версий, голые 10-значные номера),
  снижены оценкой уверенности и порогом `MIN_CONFIDENCE`, но не исключены:
  группа цифр вида `12 34 567890` без слова «заказ»/«артикул» рядом
  по-прежнему принимается за паспорт, так как серия парами - признак формата.
- Обратная сторона порога: паспорт из 10 цифр без слова «паспорт» рядом и
  без парной записи серии, а также IP без слова «IP»/«адрес» рядом по
  умолчанию не маскируются (`MIN_CONFIDENCE=0` отключает фильтрацию).
- Морфологический фильтр отбрасывает одиночное словарное слово, помеченное
  Natasha как PER, если перед ним нет маркера персоны: так теряется
  фамилия-омоним («Гусь») и название улицы без «ул.» («адрес Речная 63»).
  Для таких строк используйте `DENY_LIST`.
- Allow-список сравнивает спан целиком: если Natasha захватила лишнее слово
  вместе с названием («ООО Ромашки сегодня»), спан не совпадёт с записью и
  будет замаскирован. Deny-запись из нескольких слов не найдётся, если
  слова разнесены по разным блокам текста PDF.
