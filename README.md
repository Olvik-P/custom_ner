# PrivacyGuard Pipeline

Production-ready трёхслойный конвейер анонимизации PII (персональных данных) перед отправкой в LLM API с возможностью последующей деанонимизации ответа.

## Архитектура

```
Входной текст
    │
    ▼
┌─────────────────┐
│  PatternMatcher │  ← Слой 1: Regex (телефоны, email, паспорта, ИНН, СНИЛС, карты, IP, URL, координаты)
│  (detection/)   │    с валидацией (Luhn для карт, phonenumbers для телефонов)
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   NatashaNER    │  ← Слой 2: Нейросетевой NER (PER, LOC, ORG, адреса)
│  (detection/)   │    Библиотека Natasha от Яндекса
└────────┬────────┘
         │
         ▼
┌─────────────────────┐
│ ContextualValidator │  ← Слой 3: Разрешение конфликтов, whitelist, эвристики
│     (detection/)    │    "Ромашка" → цветок, не PER
└────────┬────────────┘
         │
         ▼
┌─────────────────┐
│     Masker      │  ← Генерация токенов <TYPE_UUID8>, замена от конца к началу
│   (masker.py)   │    Сохранение mapping'а в памяти
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│   LLM Proxy     │  ← Отправка обезличенного текста в OpenAI/Claude API
│  (llm_proxy.py) │    Получение ответа с токенами
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│    Demasker     │  ← Обратная замена токенов → оригинальные значения
│   (masker.py)   │    Очистка mapping'а из памяти
└────────┬────────┘
         │
         ▼
   Финальный ответ
```

## Установка на Windows

### 1. Установка Python 3.12 через winget

```powershell
winget install Python.Python.3.12
```

Проверьте установку:

```powershell
python --version
# Python 3.12.x
```

### 2. Клонирование и настройка проекта

```powershell
cd privacyguard_pipeline
python -m venv .venv
.venv\Scripts\activate
pip install -e .
```

### 3. Настройка .env

Скопируйте `.env.example` в `.env`:

```powershell
copy .env.example .env
```

Отредактируйте `.env`, укажите ваш API-ключ:

```
OPENAI_API_KEY=sk-your-key-here
LLM_MODEL=gpt-4o-mini
```

### 4. Первый запуск (скачивание моделей Natasha)

При первом запуске модели Natasha скачаются автоматически:

```powershell
python main.py "Тестовый текст"
```

## Использование

### CLI режим

```powershell
# Простой запрос
python main.py "Пациент Иванов Пётр Сергеевич, тел. +7(916)123-45-67"

# С системным промптом
python main.py --system "Ты — медицинский ассистент" -- "Пациент Иванов, диагноз: гипертония"
```

### Программный режим

```python
import asyncio
from main import process

async def main():
    result = await process(
        "Пациент Иванов Пётр Сергеевич, тел. +7(916)123-45-67"
    )
    print(result["anonymized_text"])
    print(result["llm_response"])
    print(result["stats"])

asyncio.run(main())
```

## Пример работы

**Вход:**
```
Пациент Иванов Пётр Сергеевич, 1975 г.р., адрес: г. Москва,
ул. Тверская, д.5, кв.17, полис ОМС 1234567890123456,
тел. +7(916)123-45-67. Диагноз: гипертония.
```

**Обезличенный текст:**
```
Пациент <PER_F50375AE>, 1975 г.р., адрес: <LOC_40820F6D>,
<LOC_88736FB3>, <LOC_54DE3CD7>, <LOC_F7F136EE>, полис ОМС 1234567890123456,
тел. <PHONE_BF0DE2ED>. Диагноз: гипертония.
```

Каждый компонент адреса — город, улица, дом, квартира — маскируется
отдельным токеном, а не только город/улица целиком (см. "Как это работает"
выше). Номер полиса в этом примере не распознаётся ни одним из типов PII
пайплайна — маскируются только поддерживаемые сущности (ФИО, телефон,
email, паспорт, ИНН, СНИЛС, ОГРН, банковская карта — с проверкой по
алгоритму Луна, из-за чего этот конкретный 16-значный номер не проходит
как карта, — IP, координаты, адрес).

**Финальный ответ (демаскированный):**
```
Пациент Иванов Пётр Сергеевич находится в группе риска по гипертонии.
Рекомендовано наблюдение по месту жительства: г. Москва.
```

## Обезличивание PDF

Помимо текстового конвейера, пакет умеет обезличивать PII прямо в PDF-файлах
(`privacyguard_pipeline/pdf/`) — договорах, сканах и т. п. Найденные
фрагменты **физически удаляются** из файла (текстовые объекты вырезаются,
пиксели изображений под областью редакции закрашиваются), а не просто
скрываются чёрным прямоугольником поверх текста, который оставался бы
извлекаемым.

### Установка

Это опциональная зависимость — базовый текстовый/LLM-пайплайн её не требует:

```powershell
cd privacyguard_pipeline
pip install -e ".[pdf]"
```

Для страниц без текстового слоя (сканы) используется OCR-фолбэк на базе
`pytesseract`, которому дополнительно нужен **системный** Tesseract с
русской языковой моделью — он не ставится через `pip`:

```powershell
winget install --id UB-Mannheim.TesseractOCR
```

Убедитесь, что `tesseract.exe` есть в `PATH` и что вместе с ним установлен
языковой пакет `rus` (в installer'е UB-Mannheim он отмечается отдельным
чекбоксом "Russian").

> OCR-путь менее надёжен, чем текстовый слой: ошибки распознавания
> (спутанные цифры, "0"/"O" и т. п.) могут привести к тому, что PII на
> сканированной странице не будет найдена. Используйте статистику результата
> (`redacted_by_type`, `pages_processed`), чтобы заметить страницы с
> подозрительно малым числом найденных PII, и проверяйте такие страницы
> вручную.

### Использование

```python
from privacyguard_pipeline import PDFAnonymizer

anonymizer = PDFAnonymizer()
result = anonymizer.anonymize(
    input_pdf="договор.pdf",
    output_pdf="договор_обезличенный.pdf",
    # entity_types=["PER", "PHONE"],  # только эти типы, если задано
)

print(f"Обработано страниц: {result.pages_processed}")
print(f"Найдено PII: {result.total_spans_redacted}")
print(f"По типам: {result.redacted_by_type}")
print(f"Успех: {result.success}")
```

Если `pdf`-зависимости не установлены, обращение к `PDFAnonymizer` выдаёт
понятную ошибку `PDFDependencyError` с инструкцией по установке — при этом
импорт остальной части пакета (текстовый/LLM-пайплайн) не затрагивается.

## HTTP API

Помимо CLI/программного использования, пакет умеет отдавать тот же
конвейер по HTTP — чтобы его можно было переиспользовать из других
проектов независимо от языка/стека (не на Python, без Docker и т. п.),
а не только встраивать как Python-зависимость. Это тонкий слой поверх
уже существующего `PrivacyGuardPipeline.process()` / `PDFAnonymizer` —
никакой новой логики детекции/маскирования/LLM-проксирования,
только HTTP-обёртка.

### Установка

Опциональная зависимость — базовый текстовый/LLM-пайплайн и CLI её не
требуют:

```powershell
cd privacyguard_pipeline
pip install -e ".[api]"
```

Ставит FastAPI, uvicorn и python-multipart (нужен FastAPI для разбора
multipart-загрузки файлов в `/v1/anonymize/pdf`).

### Настройка

В `.env` (см. `.env.example`):

```
API_KEY=ваш-секретный-ключ
API_KEY_REQUIRED=true
API_PORT=8420
```

- **`API_KEY`** — секрет, который клиенты передают в заголовке
  `X-API-Key`. Сверяется constant-time сравнением
  (`hmac.compare_digest`), чтобы не давать утечку через тайминг-атаку.
- **`API_KEY_REQUIRED=false`** отключает проверку ключа — только для
  локальной разработки. При старте с отключённой проверкой сервис
  всегда пишет явное предупреждение в лог (независимо от `LOG_LEVEL`),
  чтобы такая конфигурация не осталась незамеченной на реальном
  окружении.
- **`API_PORT`** — порт, который слушает сервер (по умолчанию `8420` —
  умышленно не 8000/8080/5000/3000, чтобы не пересекаться с типичными
  занятыми портами других сервисов).

### Запуск

Локально (после `pip install -e ".[api]"`):

```powershell
cd privacyguard_pipeline
python -m privacyguard_pipeline.api
```

Через Docker — см. раздел "Docker" ниже.

### Эндпоинты

Все, кроме `/health`, требуют заголовок `X-API-Key` — без него или с
неверным значением сервер отвечает `401 Unauthorized`, не выполняя
никакой обработки PII.

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/health` | Liveness-check, без аутентификации, без PII |
| POST | `/v1/anonymize` | `{text, system_prompt?}` → `{anonymized_text, llm_response, stats}` |
| POST | `/v1/anonymize/pdf` | multipart PDF → редактированный PDF (нужна `pdf`-экстра) |
| GET | `/v1/stats` | Статистика сессии — только типы/количества сущностей |

#### `POST /v1/anonymize`

```bash
curl -X POST http://localhost:8420/v1/anonymize \
    -H "X-API-Key: ваш-секретный-ключ" \
    -H "Content-Type: application/json" \
    -d '{"text": "Пациент Иванов Пётр Сергеевич, тел. +7(916)123-45-67"}'
```

Ответ — та же структура, что уже возвращает программный
`PrivacyGuardPipeline.process()`:

```json
{
  "anonymized_text": "Пациент <PER_C7D2F8E2>, тел. <PHONE_98D31C0A>",
  "llm_response": "Имя пациента: Иванов Пётр Сергеевич\nТелефон: +7(916)123-45-67",
  "stats": {
    "entity_counts": {"PER": 1, "PHONE": 1},
    "total_entities_detected": 2,
    "processing_time_ms": 95.01
  }
}
```

Каждый запрос получает собственный экземпляр `Masker` — соответствие
токен→значение одного запроса никогда не видно и не может быть
очищено другим параллельным запросом (проверено вручную двумя
одновременными запросами с разным PII). Детектор PII и LLM-прокси при
этом общие на процесс (создаются один раз при старте) — это не
PII-хранящее состояние, а переиспользование дорогого в создании
ресурса: пересоздание детектора на каждый запрос заново грузило бы
модели Natasha, а пересоздание LLM-прокси теряло бы пул HTTP-соединений.

#### `POST /v1/anonymize/pdf`

```bash
curl -X POST http://localhost:8420/v1/anonymize/pdf \
    -H "X-API-Key: ваш-секретный-ключ" \
    -F "file=@договор.pdf;type=application/pdf" \
    -o договор_redacted.pdf
```

Тело ответа — редактированный PDF (`application/pdf`), статистика идёт
в заголовках, а не в теле, так как тело занято файлом:

| Заголовок | Значение |
|-----------|----------|
| `X-Pages-Processed` | число обработанных страниц |
| `X-Total-Spans-Redacted` | всего вычеркнуто PII-фрагментов |
| `X-Redacted-By-Type` | JSON вида `{"PER": 4, "PHONE": 2, ...}` |

Загрузка ограничена 20 МБ (`413 Request Entity Too Large` при
превышении). Если `pdf`-зависимости не установлены — `501 Not
Implemented` с понятным текстом ошибки, а не общий сбой. Если
редактирование не удалось (повреждённый файл и т. п.) — `422
Unprocessable Entity`.

#### `GET /v1/stats`

Отдаёт то же, что `AuditLogger.get_stats()` — только типы/количества
найденных сущностей за сессию, никогда исходные или демаскированные
значения:

```json
{
  "session_duration_seconds": 30.75,
  "total_requests": 2,
  "successful_requests": 2,
  "failed_requests": 0,
  "entity_counts": {"PER": 4, "PHONE": 3},
  "total_entities_detected": 7
}
```

## MCP-сервер

Локальный MCP-сервер защищает не вызов внешнего LLM API (для этого уже
есть HTTP API выше), а саму модель-агента (например, Claude
Desktop/Code), которая работает с текстом/файлами пользователя через
MCP: инструменты обезличивают содержимое до того, как оно попадёт в
контекст агента. Работает поверх stdio как локальный дочерний процесс,
запускаемый самим MCP-хостом — без сетевого порта и без API-ключа
(доверие обеспечивается тем, что процесс порождён самим хостом).

### Установка

```powershell
cd privacyguard_pipeline
pip install -e ".[mcp]"
```

Для инструмента `anonymize_pdf`/`detect` по PDF дополнительно нужна
экстра `pdf` (`pip install -e ".[pdf,mcp]"`).

### Настройка

В `.env` (см. `.env.example`):

```
MCP_HANDLE_TTL_SECONDS=300
```

`mask` и `demask` — два разных вызова в рамках одного диалога:
`mask` возвращает handle, `demask` принимает его позже. Если `demask`
так и не был вызван (диалог прерван и т. п.), запись handle → PII
автоматически удаляется из памяти процесса по истечении этого TTL.

### Запуск

Настройте MCP-хост (например, Claude Desktop/Code) на запуск локальной
команды:

```json
{
  "mcpServers": {
    "privacyguard-pipeline": {
      "command": "python",
      "args": ["-m", "privacyguard_pipeline.mcp_server"],
      "env": { "MCP_HANDLE_TTL_SECONDS": "300" }
    }
  }
}
```

Через Docker (тот же образ, что и для HTTP API — см. раздел "Docker"
ниже; обязательно `-i`, без `-p`, так как транспорт здесь stdio, а не
сеть):

```bash
docker run -i --env-file privacyguard_pipeline/.env ner-pipeline python -m privacyguard_pipeline.mcp_server
```

### Инструменты

| Инструмент | Вход | Выход |
|---|---|---|
| `mask` | `text` | `{masked_text, handle}` |
| `demask` | `handle, text` | `{text}` |
| `mask_file` | `file_path` | `{masked_path, handle}` |
| `close_masked_file` | `handle` | `{status}` |
| `anonymize_pdf` | `input_path`, `output_path?` | `{output_path, pages_processed, total_spans_redacted, redacted_by_type}` |
| `detect` | `file_path` | `{entity_counts}` (текст) или `{pages: {"1": {...}, ...}}` (PDF) |

- **`mask`/`demask`** — реальные значения PII никогда не входят в
  ответ `mask`. Содержательную обработку между ними (то, что раньше
  делал внешний LLM API в HTTP-пути) выполняет сам вызывающий агент —
  ни один из этих инструментов не обращается к LLM API. Повторный
  `demask` с уже использованным или неизвестным/просроченным `handle`
  завершается ошибкой инструмента.
- **`mask_file`/`close_masked_file`** — тот же принцип, что у `mask`, но
  для локального файла (текстового или PDF), который агенту иначе
  пришлось бы прочитать напрямую, минуя сервер. Сервер сам читает файл
  (для PDF — извлекает текст постранично, включая OCR-фолбэк) и
  возвращает путь к плоскому текстовому файлу с PII, заменённым на
  токены, вместе с `handle` — содержимое в ответе на сам вызов не
  передаётся. Демаскирование, как и у `mask`, происходит через `demask`
  с тем же `handle`, но только в тексте ответа агента — сам
  маскированный файл никогда не демаскируется, а просто удаляется с
  диска (автоматически при `demask`, либо явно через
  `close_masked_file`, если ответ не должен содержать реальные значения
  PII вовсе — например, "есть ли в документе пункт про сроки").
- **`anonymize_pdf`** — то же необратимое редактирование PDF, что и в
  `POST /v1/anonymize/pdf` выше, но без HTTP: сервер сам читает
  `input_path` и пишет результат по `output_path` (или рядом с
  исходником, если не задан) — содержимое файла не передаётся ни в
  запросе, ни в ответе инструмента, только путь и статистика. Прочитать
  результат можно напрямую с диска. Пары для восстановления нет —
  редактирование необратимо.
- **`detect`** — сервер сам читает файл по переданному пути; ни
  содержимое файла, ни сами значения найденного PII не попадают в
  ответ, только количество сущностей по типу (постранично для PDF).
  Полезно как быстрая проверка "что вообще есть в этом файле" перед
  тем, как решать, гнать ли его через `mask_file`/`anonymize_pdf`, или
  можно читать напрямую (если сущностей не найдено).

## Docker

Образ (`python:3.12-slim` + системный Tesseract с русской моделью +
все Python-зависимости, включая `pdf`-, `api`- и `mcp`-экстры) избавляет от
ручной настройки Windows-окружения — не нужно ни `winget`, ни
выставлять `PATH`/`TESSDATA_PREFIX` вручную, ни ставить FastAPI
локально.

Команды ниже написаны так, чтобы копироваться один в один и в PowerShell, и
в Git Bash/WSL/cmd.exe — одна строка на команду, прямые слэши в путях (не
`\`, который в bash обрезает следующий символ — `privacyguard_pipeline\.env`
в bash превращается в `privacyguard_pipeline.env` и валится с "file not
found").

```bash
# Собрать образ (из корня репозитория)
docker build -t ner-pipeline .

# По умолчанию контейнер поднимает HTTP API и слушает порт 8420 —
# см. раздел "HTTP API" выше. --name делает имя контейнера постоянным
# (ner-pipeline), а не случайно сгенерированным при каждом запуске
docker run --name ner-pipeline --env-file privacyguard_pipeline/.env -p 8420:8420 ner-pipeline

# CLI остаётся доступным в том же образе через переопределение команды
docker run --env-file privacyguard_pipeline/.env ner-pipeline python main.py "Пациент Иванов Пётр Сергеевич, тел. +7(916)123-45-67"

# Без ключа — пайплайн отработает детекцию/маскирование и корректно
# деградирует на шаге обращения к LLM
docker run ner-pipeline python main.py "Текст с PII"

# Интерактивная оболочка внутри контейнера
docker run -it ner-pipeline bash

# Обезличивание PDF с файлами с хоста через volume
docker run -v ${PWD}:/data ner-pipeline python -c "from privacyguard_pipeline import PDFAnonymizer; PDFAnonymizer().anonymize('/data/in.pdf', '/data/out.pdf')"
```

Раз имя контейнера постоянное, повторный `docker run --name ner-pipeline
...` при уже существующем (даже остановленном) контейнере с этим именем
упадёт с `Conflict. The container name "/ner-pipeline" is already in
use`. Чтобы просто перезапустить уже созданный контейнер — `docker start
ner-pipeline`; чтобы пересоздать его заново (например, после
`docker build` новой версии образа) — сначала `docker rm -f
ner-pipeline`, затем повторить `docker run`.

> Образ и контейнер раньше назывались `privacyguard-pipeline` — если у
> вас остался запущенный контейнер под старым именем, снимите его
> командой `docker rm -f privacyguard-pipeline` перед переходом на
> `ner-pipeline`.

Образ можно использовать и как базовый (`FROM ner-pipeline`)
для Dockerfile'ов других проектов, которым нужен этот пайплайн, — не
только запускать напрямую.

### Смоук-тесты через Docker

`docker_test.py` и `docker_test_pdf.py` в корне репозитория монтируют
весь репозиторий в контейнер (`/workspace`), поднимают там HTTP API
(`python -m privacyguard_pipeline.api`) и реально бьют по нему по
HTTP — `POST /v1/anonymize` и `POST /v1/anonymize/pdf` соответственно
— так же, как это делал бы внешний клиент. Поскольку сервер стартует
из смонтированного `/workspace`, тестируется **текущий код с диска**,
а не то, что было запечено в образ при последней сборке — не нужно
пересобирать образ между правками ради проверки. Оба скрипта сами
поднимают и останавливают контейнер (порт `8420`, случайный/фиксированный
тестовый `API_KEY` — не тот, что в вашем `.env`):

```bash
docker build -t ner-pipeline .   # один раз

python docker_test.py                     # текстовый пайплайн через API
python docker_test_pdf.py [in.pdf] [out.pdf]  # PDF через API,
                                               # включая OCR-фолбэк
                                               # (Tesseract уже внутри
                                               # образа)
```

## Ключевые возможности

- **Трёхслойная детекция**: Regex + Natasha NER + контекстная валидация
- **Graceful degradation**: при недоступности Natasha работает только PatternMatcher
- **Безопасность**: mapping токен→значение только в RAM, очищается после ответа
- **Асинхронность**: полная async/await архитектура
- **Аудит**: логирование типов PII (не значений!), статистика сессии
- **Edge cases**: телефоны без пробелов, слитные паспорта, омонимы
- **Обезличивание PDF**: та же детекция, но с необратимой редакцией внутри
  PDF-файлов (текстовый слой + OCR-фолбэк для сканов)
- **HTTP API**: тот же конвейер поверх аутентифицированного HTTP-интерфейса
  для переиспользования из других проектов/языков (опционально)
- **MCP-сервер**: локальный stdio-сервер (`mask`/`demask`/`anonymize_pdf`/
  `detect`), защищающий вызывающего MCP-агента от прямого доступа к сырым
  значениям PII (опционально)

## Безопасность

- API-ключи (LLM и HTTP API) читаются из `.env`, никогда не логируются
- Словарь соответствий (токен → значение) существует только в RAM
- После получения ответа от LLM словарь немедленно очищается
- В лог попадают только типы сущностей, не значения
- Обезличивание PDF физически удаляет PII из файла (`add_redact_annot` +
  `apply_redactions`), а не рисует прямоугольник поверх извлекаемого текста
- HTTP API: `X-API-Key` сверяется constant-time сравнением
  (`hmac.compare_digest`); каждый запрос на анонимизацию получает
  собственный `Masker`, изолируя маскирование от параллельных запросов
- MCP-сервер: ни один инструмент не обращается к внешнему LLM API;
  соответствие `handle → Masker` живёт только в памяти процесса и
  автоматически удаляется по TTL, если `demask` так и не был вызван
