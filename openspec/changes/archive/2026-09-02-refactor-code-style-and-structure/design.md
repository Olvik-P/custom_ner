## Context

Три независимых, но выполняемых одним change'ем изменения над
`privacyguard_pipeline/` — см. `proposal.md` за мотивацией. Ограничение:
публичный API пакета (`main.process`, `PrivacyGuardPipeline`, CLI) не должен
измениться — это чистая внутренняя переработка.

## Goals / Non-Goals

**Goals:**
- Физически выделить детекцию PII в подпакет `detection/` (Вариант A из
  обсуждения — только детекция, т.к. это единственное место с тремя
  под-слоями подряд).
- Единый стиль кавычек (`'`) во всём пакете, закреплённый в tooling, а не
  только вручную сделанный один раз.
- Убрать необъяснённые числа/литералы из логики детекции, маскирования,
  LLM-прокси и обрезки текста в `constants.py`.

**Non-Goals:**
- Не меняем `config.py` (Pydantic `Settings`) — его дефолты уже именованы
  через `Field(default=...)`.
- Не трогаем цифры длины внутри regex в `_patterns.py` → `patterns.py`
  (паспорт/ИНН/СНИЛС/карта/ОГРН) — вынесение их из самого паттерна снижает
  читаемость регулярки сильнее, чем помогает.
- Не меняем поведение пайплайна, сигнатуры публичных функций/классов,
  формат токенов, структуру `stats`/`audit` — только расположение файлов,
  имена внутренних модулей и литералов.

## Decisions

**1. Раскладка `detection/` (Вариант A, не Вариант B).**
Только детекция уходит в подпакет — там реально три слоя, работающих
последовательно (`PatternMatcher` → `NatashaNER` → `ContextualValidator`),
плюс общие `common.py`/`patterns.py`/`validators.py`. `masker.py`,
`llm_proxy.py`, `audit.py`, `pipeline.py` каждый уже равен одному слою —
оборачивать их в папку из одного файла не даёт выгоды, только лишний уровень
импортов. `_`-префикс у файлов детекции убирается: инкапсуляция теперь
выражена структурно (подпакет), а не соглашением об именах.
`detection/__init__.py` реэкспортирует `PIIDetector`, `PIISpan`,
`DetectionResult` — так `pipeline.py`/`masker.py` меняют только путь
импорта (`privacyguard_pipeline.detection`), а не количество импортируемых
имён.

Новые имена файлов внутри `detection/` (убираем `_pattern_matcher.py` и
префикс `pii_` из `pii_detector.py`, т.к. пакет сам называется `detection`):
`common.py`, `patterns.py`, `validators.py`, `pattern_matcher.py`,
`natasha_ner.py`, `contextual_validator.py`, `detector.py`.

**2. Кавычки через `ruff format`, а не ручную замену.**
Вместо ручной правки ~1000+ строк с `"` добавляем
`[tool.ruff.format]` c `quote-style = "single"` и один раз прогоняем
`uv run ruff format .` — это тот же движок, что и `ruff check`, уже в
dev-зависимостях, конвертация детерминирована и не пропустит f-strings/
экранирования. Дополнительно в `[tool.ruff.lint]` добавляется `Q`
(flake8-quotes), чтобы будущий код, добавленный не через `ruff format`,
тоже проверялся линтером.
Docstring'и (`"""..."""`) **не переводим** в `'''...'''` — тройные двойные
кавычки для docstring'ов это отдельная, устоявшаяся PEP 257-конвенция, и
`ruff format` по умолчанию не трогает стиль кавычек docstring'ов при смене
`quote-style` для обычных строк. Это ожидаемое поведение инструмента, но
после форматирования всё равно нужно визуально сверить пару файлов
(`main.py`, `pipeline.py` — там больше всего docstring'ов), на случай
расхождения с ожиданием.

**3. `constants.py` — плоский модуль на верхнем уровне пакета.**
Один файл, а не по константе рядом с каждым модулем — потому что многие
числа (confidence, окно контекста) логически принадлежат detection-слою,
но используются/сравниваются между слоями (например, `pipeline.py` не
интерпретирует confidence, но `_contextual_validator.py` присваивает разные
уровни в зависимости от источника). Раскладывать константы по под-модулям
`detection/constants.py` vs корневой `constants.py` добавило бы
неоднозначность, куда класть общие вроже HTTP-таймаутов. Один
`constants.py` с секциями-комментариями (`# Detection confidence`,
`# Masking`, `# LLM proxy`, `# Text truncation`) — самый простой вариант,
которого достаточно для текущего размера пакета.

Состав констант (числа берутся из текущего кода без изменения значений):
- Detection: `PATTERN_CONFIDENCE = 0.95`, `NATASHA_NER_CONFIDENCE = 0.85`,
  `NATASHA_ADDR_CONFIDENCE = 0.75`, `CONTEXT_RESOLVED_CONFIDENCE = 0.7`,
  `CONTEXT_LOOKBACK_WORDS = 3`.
- Validators: `INN_VALID_LENGTHS = (10, 12)`, `PASSPORT_DIGIT_COUNT = 10`,
  `IP_OCTET_MIN = 0`, `IP_OCTET_MAX = 255`, `LUHN_MODULO = 10`,
  `LUHN_DOUBLE_SUBTRACT = 9`.
- Masking: `TOKEN_HEX_LENGTH = 8`.
- LLM proxy: `HTTP_TIMEOUT_SECONDS = 120.0`,
  `HTTP_CONNECT_TIMEOUT_SECONDS = 30.0`, `DEFAULT_TEMPERATURE = 0.3`,
  `DEFAULT_MAX_TOKENS = 4096`, `CLAUDE_API_VERSION = '2023-06-01'`,
  `HTTP_STATUS_UNAUTHORIZED = 401`.
- Text truncation: `PANEL_PREVIEW_CHARS = 500` (main.py),
  `LOG_PREVIEW_CHARS = 100` (pipeline.py debug-лог),
  `AUDIT_PREVIEW_CHARS = 200` (audit.py).

`luhn_check`'а внутренний `% 2 == 1` (чётность позиции) не выносится —
это структурная часть алгоритма Луна, а не конфигурируемое значение,
как и `LUHN_MODULO`/`LUHN_DOUBLE_SUBTRACT` (их вынос — скорее для
документирования смысла "почему 9", чем для повторного использования).

## Risks / Trade-offs

- [Импорты по всему пакету меняются одновременно с переносом в `detection/`]
  → mitigation: перенос и правка импортов делаются одним task-шагом с
  последующим прогоном `uv run mypy .` и `uv run pytest` (когда появятся
  тесты) / ручным smoke-запуском `test.py`, чтобы поймать пропущенный импорт
  сразу, а не после кавычек/констант поверх сломанной структуры.
- [`ruff format` с `quote-style = single` может задеть строки, где замена
  кавычки меняет смысл — например, строки, уже содержащие `'` внутри]
  → mitigation: `ruff format` сам решает эту коллизию через экранирование/
  выбор кавычки без потери корректности (это его штатная задача), но стоит
  визуально сверить diff перед коммитом, а не просто доверять "не упало".
- [Порядок выполнения трёх изменений в одном коммите усложняет ревью]
  → mitigation: тройной порядок в `tasks.md` — сначала структура (перенос +
  импорты), потом константы (легко проверяемая замена значений 1:1), потом
  кавычки (полностью механическая, автоматическая замена последним шагом,
  чтобы не переписывать кавычки дважды при переносе файлов).

## Migration Plan

1. Создать `detection/`, перенести файлы, снять `_`-префикс, обновить
   внутренние импорты внутри `detection/` и внешние (`pipeline.py`,
   `masker.py`) на `from privacyguard_pipeline.detection import ...`.
   Проверить `uv run mypy .` и ручной прогон (`test.py` / `main.py`).
2. Создать `constants.py`, заменить перечисленные литералы на импорт
   констант, значения не менять.
3. Добавить `[tool.ruff.format] quote-style = "single"` и `Q` в
   `[tool.ruff.lint].select`, прогнать `uv run ruff format .`, затем
   `uv run ruff check .`. Визуально сверить, что docstring'и остались в
   `"""`.
4. Финальная проверка: `uv run mypy .`, `uv run ruff check .`, ручной
   `uv run python main.py "тест"` (или `test.py`, если есть ключ LLM).

Откат: изменения затрагивают только структуру/стиль в рамках одной ветки —
откат стандартным `git revert`/сбросом ветки, без миграций данных или
внешних систем.
