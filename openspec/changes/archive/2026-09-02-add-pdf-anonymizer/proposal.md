## Зачем

Пользователям нужно обезличивать PII в русскоязычных PDF-документах
(договоры, подписанные сканы) перед их передачей или архивированием — не
только в тексте, отправляемом в LLM. Существующий `PIIDetector` уже умеет
находить русскоязычные PII — расширение на PDF переиспользует этот слой
детекции вместо создания отдельного.

## Что меняется

- Добавляется новый подпакет `pdf/` (по образцу уже существующего подпакета
  `detection/`), который обезличивает PII прямо внутри PDF-файлов.
- Текст извлекается **на уровне строки/блока** (а не по сырым font-run
  span'ам PyMuPDF), с восстановлением контекста, достаточного для того,
  чтобы `PIIDetector` — включая lookback-эвристику
  `ContextualValidator` — работал так, как задуман. Найденные офсеты
  символов затем мапятся обратно на bbox отдельных слов через
  `page.get_text("words")`.
- Для страниц без извлекаемого текстового слоя (сканы) предусмотрен
  OCR-фолбэк (`pytesseract` + системный Tesseract, русская языковая пакет),
  который отдаёт поток слово+bbox той же формы, что и текстовый путь —
  благодаря этому детекция и редакция дальше идут по одному общему коду.
- Найденные фрагменты зачёркиваются через настоящую редакцию PyMuPDF
  (`page.add_redact_annot` + `page.apply_redactions(images=...)`), которая
  физически удаляет текстовые объекты и закрашивает пиксели изображения под
  прямоугольником редакции — а не рисует косметический чёрный прямоугольник
  поверх текста, который остаётся извлекаемым.
- `PyMuPDF` и `pytesseract` добавляются как опциональная группа зависимостей
  `pdf` (`uv sync --extra pdf`), а не как основная зависимость — базовый
  пайплайн остаётся лёгким для тех, кому нужен только текстовый/LLM-прокси
  путь. По аналогии с уже существующим паттерном graceful degradation для
  Natasha, импорт подпакета `pdf` без установленного extra выдаёт понятную,
  actionable-ошибку, а не падает где-то ещё при импорте.

## Возможности (Capabilities)

### Новые возможности
- `pdf-anonymization`: извлечение текста из страниц PDF (с
  layout-aware маппингом офсет→bbox), поиск PII в этом тексте через
  существующий `PIIDetector`, и создание обезличенного PDF, где найденные
  фрагменты необратимо удалены (текстовые объекты вырезаны, пиксели
  изображений закрашены), а не просто визуально скрыты.

### Изменённые возможности
(нет — эта фича только добавляет новую возможность; поведение на уровне
существующих спеков не меняется)

## Влияние (Impact)

- Новый подпакет `privacyguard_pipeline/pdf/` (`anonymizer.py` —
  публичный API, `text_extractor.py` — сбор текста построчно/по блокам +
  маппинг офсет→bbox, `ocr.py` — Tesseract-фолбэк, отдающий тот же формат
  слово/bbox, `renderer.py` — редакция через
  `add_redact_annot`/`apply_redactions`).
- `pyproject.toml`: новая опциональная группа зависимостей `pdf`
  (`PyMuPDF`, `pytesseract`); бамп версии.
- `privacyguard_pipeline/__init__.py`: экспорт `PDFAnonymizer` и его
  результирующего типа, с защитой, чтобы основной пакет по-прежнему
  импортировался без установленного extra `pdf`.
- Для OCR-фолбэка требуется системный Tesseract с русской языковой пакетом
  (`rus`), установленный и доступный в `PATH` — задокументировано в README,
  через pip не ставится.
- Изменений в `detection/`, `masker.py`, `pipeline.py` или `llm_proxy.py`
  нет — `PIIDetector` переиспользуется как есть.
