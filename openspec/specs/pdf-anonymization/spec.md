# pdf-anonymization Specification

## Purpose

Обезличивание PII непосредственно в PDF-документах — обнаруженные фрагменты
необратимо удаляются из файла, а не просто визуально скрываются.

## Requirements

### Requirement: Редакция PII в текстовом слое PDF
Система ДОЛЖНА (SHALL) обнаруживать PII на страницах PDF, содержащих
извлекаемый текстовый слой, и формировать выходной PDF, в котором текстовые
объекты, соответствующие каждому найденному фрагменту, физически удалены, а
не только визуально закрыты.

#### Scenario: Страница с PII в текстовом слое
- **WHEN** страница PDF содержит извлекаемый текст с PII (например, номер
  телефона или ФИО)
- **THEN** система формирует обезличенную страницу, в которой
  соответствующие области больше не содержат исходный текст, а извлечение
  текста из этих областей (copy-paste, `pdftotext` и т. п.) не возвращает
  исходное значение PII

#### Scenario: Страница без PII
- **WHEN** текстовый слой страницы не содержит PII
- **THEN** страница воспроизводится без изменений, редакционные
  прямоугольники не рисуются

### Requirement: Сохранение не-PII текста при редакции
Текст, не являющийся частью найденного PII-фрагмента, ДОЛЖЕН (SHALL)
оставаться читаемым и извлекаемым после редакции — включая случай, когда
он находится в одной строке или одном внутреннем текстовом объекте PDF
вместе с редактируемым PII-фрагментом.

#### Scenario: Не-PII текст на той же строке, что и PII
- **WHEN** строка страницы содержит одновременно PII-фрагмент и текст, не
  являющийся PII
- **THEN** после редакции не-PII текст этой строки остаётся читаемым и
  извлекаемым, а сам PII-фрагмент отсутствует и визуально, и при
  извлечении текста

#### Scenario: Исходный шрифт непригоден для повторного использования
- **WHEN** шрифт, которым была набрана строка, невозможно использовать
  для отображения сохраняемого не-PII текста (например, у шрифта,
  извлечённого из PDF, отсутствуют данные, необходимые для сопоставления
  символов с глифами)
- **THEN** система использует альтернативный доступный шрифт для
  отображения сохраняемого текста вместо того, чтобы оставить этот текст
  нечитаемым или удалить его вместе с PII

### Requirement: Детекция с сохранением контекста
Система ДОЛЖНА (SHALL) запускать детекцию PII на восстановленном тексте
уровня строки/блока страницы, а не на отдельных сырых font-run фрагментах,
чтобы многословные PII-значения и контекстно-зависимая эвристика
разрешения неоднозначностей работали так же, как при детекции обычного
текста.

#### Scenario: PII разбит между шрифтовыми фрагментами внутри строки
- **WHEN** значение PII отрисовано несколькими смежными шрифтовыми
  фрагментами внутри одной строки (например, фамилия жирным шрифтом рядом с
  именем обычным начертанием)
- **THEN** система обрабатывает восстановленную строку как единый блок для
  детекции и зачёркивает bounding box'ы всех фрагментов, на которые
  распространяется найденная подстрока PII

### Requirement: OCR-фолбэк для сканированных страниц
Для страницы PDF без извлекаемого текстового слоя система ДОЛЖНА (SHALL)
выполнить оптическое распознавание текста (OCR), чтобы получить слова с их
координатами, и далее применить тот же порядок детекции и редакции, что и
для страницы с текстовым слоем.

#### Scenario: Полностью отсканированная страница
- **WHEN** страница не содержит извлекаемого текста (только изображение)
- **THEN** система распознаёт содержимое страницы через OCR, и для PII,
  найденного в распознанном тексте, в выходном файле закрашиваются
  соответствующие пиксели изображения

#### Scenario: OCR недоступен или не настроен
- **WHEN** OCR-движок не установлен или не сконфигурирован в системе
- **THEN** система сообщает явную ошибку для затронутой страницы (номер
  страницы, причина) вместо того, чтобы молча пропустить редакцию этой
  страницы или прервать обработку всего документа без объяснения

### Requirement: Гарантия необратимости редакции
Зачёркнутые фрагменты ДОЛЖНЫ (SHALL) быть удалены так, чтобы ни извлекаемый
текстовый поток, ни пиксели изображения под областью редакции не содержали
исходное значение PII.

#### Scenario: Попытка извлечь текст после редакции
- **WHEN** из обезличенного PDF извлекается текст любым стандартным
  средством извлечения текста
- **THEN** извлечённый текст не содержит ни одного зачёркнутого значения PII

### Requirement: Выборочная редакция по типу сущности
Система ДОЛЖНА (SHALL) поддерживать опциональное ограничение редакции
заданным вызывающей стороной подмножеством типов PII, оставляя остальные
найденные типы нетронутыми.

#### Scenario: Задан фильтр по типам
- **WHEN** вызывающая сторона запрашивает редакцию, ограниченную типами
  {PHONE, PER}
- **THEN** фрагменты других найденных типов не зачёркиваются, а фрагменты
  запрошенных типов зачёркиваются

#### Scenario: Ссылки не зачёркиваются по умолчанию
- **WHEN** вызывающая сторона не указывает список типов и не запрашивает
  редакцию ссылок явно
- **THEN** найденные фрагменты типа URL остаются видимыми и извлекаемыми
  в выходном файле, а остальные найденные типы PII зачёркиваются

#### Scenario: Явный запрос редакции ссылок
- **WHEN** вызывающая сторона либо явно запрашивает включение URL в
  редакцию при незаданном списке типов, либо указывает "URL" в списке
  запрошенных типов
- **THEN** найденные фрагменты типа URL зачёркиваются наравне с
  остальными запрошенными типами

### Requirement: Отчёт о результате обезличивания
Система ДОЛЖНА (SHALL) возвращать структурированный результат с числом
обработанных страниц, количеством зачёркнутых фрагментов по типам сущностей
и статусом успеха/ошибки, не раскрывая исходные значения PII.

#### Scenario: Успешное обезличивание
- **WHEN** обезличивание завершается без ошибок
- **THEN** результат сообщает `success=true`, количество найденных
  фрагментов по каждому типу и число обработанных страниц, совпадающее с
  входным документом

#### Scenario: Ошибка в процессе обработки
- **WHEN** во время обработки входного PDF возникает невосстановимая ошибка
- **THEN** результат сообщает `success=false` с описанием ошибки, и в файловой
  системе не остаётся частично обезличенный выходной файл, который можно
  принять за полностью безопасный

### Requirement: Валидация входных данных
Система ДОЛЖНА (SHALL) проверять, что путь к входному файлу указывает на
существующий, читаемый PDF-файл, прежде чем начинать обработку, и ДОЛЖНА
(SHALL) немедленно выдавать явную ошибку при отсутствующем или невалидном
входном файле, а не создавать пустой выходной файл.

#### Scenario: Входной файл отсутствует
- **WHEN** путь `input_pdf` не существует
- **THEN** система выдаёт ошибку "файл не найден" до начала какой-либо
  обработки

### Requirement: Изоляция опциональных зависимостей
Использование возможности обезличивания PDF без установленных
опциональных зависимостей ДОЛЖНО (SHALL) приводить к явной, actionable
ошибке с указанием отсутствующей зависимости и способа её установки, и НЕ
ДОЛЖНО (SHALL NOT) влиять на возможность импортировать или использовать
остальную часть пакета (текстовый/LLM-пайплайн).

#### Scenario: Не установлен extra "pdf"
- **WHEN** вызывающая сторона импортирует или использует функциональность
  обезличивания PDF без установленной опциональной группы зависимостей
  "pdf"
- **THEN** выдаётся понятная ошибка с указанием отсутствующей зависимости и
  инструкцией по установке, а импорт остальных модулей основного пакета
  проходит без ошибок
